# v0.20.0 — Adoption Waves 2–4, Documentation Coherence System, Independent Audit

Release date: 2026-07-01

MINOR release under [`docs/RELEASING.md`](../docs/RELEASING.md) §1.2
(backward-compatible additions: new ADRs, new agentic surface, new
scaffolded-service files and Makefile targets, no renamed/removed contract).
This release closes the remainder of the industry-adoption program
([`docs/audit/ACTION_PLAN_ADAPTABILITY.md`](../docs/audit/ACTION_PLAN_ADAPTABILITY.md)
Waves 2–4), ships a new cross-document coherence system, and records an
independent Staff/Lead verification pass over all of it — including real
functional defects found and fixed before this tag.

## What changed

### Wave 2 — Local-first stack profiles (ADR-033)

- Three stack profiles — `local` / `staging` / `prod` — selectable at
  scaffold time via a Copier `profile` question (default `local`) and
  switchable afterward via `make switch-profile PROFILE=<name>` or the new
  `stack-switch` skill (CONSULT) / `/stack-switch` workflow.
- `configs/profiles/{local,staging,prod}.yaml` presets + a generated
  `active_profile.yaml` single source of truth; `make local-loop` chains
  train → serve → drift-check with zero cloud dependencies.
- **D-35** — a `local` profile that accepts cloud credentials or targets a
  cluster. Enforced by
  `tests/policy/test_anti_patterns.py::test_d35_local_profile_no_cloud_deps`.
- `make deploy` now refuses to run when the active profile is `local`
  (the invariant ADR-033 §2.5 specifies), verified against a real
  scaffolded render.

### Wave 3 — Recognizability & pedagogy (ADR-034)

- `docs/CCDS_MAPPING.md` (generated into every scaffolded service): a
  documentation-only mapping from this template's production layout to
  the Cookiecutter Data Science vocabulary. No directory renamed.
- `docs/TUTORIAL.md`: a narrated "notebook to production" walk-through
  tying 8 anti-patterns to the concrete failure each prevents.
- `template-onboard` skill (AUTO) + `/onboard` workflow: interviews the
  adopter and emits a schema-validated `<slug>_context.local.yaml`
  (gitignored, never secrets) capturing cloud provider, registry, MLflow
  URI, DVC remote, GitHub org, monitoring endpoint, log level, and profile.

### Wave 4 — Modernization & discoverability (ADR-035)

- `uv sync` as a first-class, additive install path (`make install-uv`);
  `requirements.txt` retained for pip-only / air-gapped adopters.
- `copier copy https://github.com/DuqueOM/ML-MLOps-Production-Template.git`
  documented as the canonical scaffolding invocation.
- `docs/PROGRESSION.md` and `docs/ADOPTION.md` updated with the new
  on-ramps.

### Documentation Coherence System (rule 16, ADR-031)

- `scripts/check_doc_coherence.py`: a deterministic, CI-blocking gate
  (sibling of the `check_*_drift.py` family) enforcing a single source of
  truth for facts restated across documents — release version, anti-pattern
  count, agentic surface counts, and ADR numbering (no silent gaps).
  Context-adaptive (skip-on-absent) so the same script runs correctly
  inside a scaffolded service, which tracks none of `VERSION` / `CHANGELOG.md`
  / `llms.txt`. Vendored into `templates/service/` with a real `make
  doc-coherence` non-agentic equivalent.
- `agentic/rules/16-doc-coherence.md` (the SSoT register + "if you touch X,
  update Y" cascade map), `agentic/skills/doc-coherence/` (the agent that
  applies the cascade under CONSULT/STOP boundaries — never renumbers an
  ADR, never rewrites a released CHANGELOG heading), `/doc-coherence`
  workflow.
- On introduction, the gate and a systematic sweep caught real drift that
  predated this release: `VERSION` lagging the CHANGELOG, a `llms.txt`
  frozen in the template's v1.3.0 era, and stale anti-pattern counts in
  both `CLAUDE.md` files.

### ADR-032 — BentoML as an optional serving backend (Proposed)

Documentation-only: records the invariant contract (D-01/D-02/D-11/D-23/
D-25/D-04) any future BentoML backend must satisfy. No code ships; the
template's FastAPI + `ThreadPoolExecutor` serving path remains the sole
default. README §"How this compares" gains a Kubeflow comparison column
and a "tools we compose with, not against" section (BentoML, Evidently).

## Independent Staff/Lead audit of Waves 2–4 (this release)

Because Waves 2–4 were implemented in a separate pass, this release
includes an independent verification: every file the ADR-033/034/035
tracker claimed to ship was checked against disk, all six drift/validator
gates were re-run, the full 679-test suite was run, and a **real**
`copier copy` render was exercised end-to-end (scaffold with
`profile=local` → `make deploy` blocked → `make onboard` → validate the
generated context file → `make switch-profile PROFILE=staging` →
`make deploy` proceeds). This surfaced and fixed:

- A **functional bug**: `/onboard`'s own schema-validation step validated
  its adopter-infrastructure YAML against `context.schema.json` (the
  ADR-023 company/project risk-context schema, which rejects any other
  shape via `additionalProperties: false`) — validation would have failed
  on every invocation. Fixed with a dedicated `adopter_context.schema.json`.
- A **missing scaffolded-service `.gitignore`** (had never existed, not
  specific to this release, but a hard blocker for `/onboard`'s own
  precondition check). Added, including the ADR-023/029
  `*_context.local.yaml` pattern.
- An **unenforced ADR-033 invariant** (`make deploy` did not actually
  block on the `local` profile). Fixed and verified in both directions.
- A **pre-existing `make deploy` / `deploy.sh` CLI-flag mismatch**,
  surfaced by the end-to-end verification. Fixed.
- A **PR-R2-12 non-agentic-on-ramp gap**: the two new workflows had no
  `make` target registered. Fixed (`make onboard`, `make switch-profile`
  mapped) and documented in `docs/ADOPTION.md`.
- Vendored-runtime drift (new skills/workflows not yet propagated into
  `templates/service/agentic/`) and several stale `D-01..D-34` citations
  left over from the D-35 bump, across `ADR-014`, `rule-audit/SKILL.md`,
  `docs/TUTORIAL.md` (a non-existent test-name citation), `README.md` (a
  non-existent test-path citation), and both `ADOPTION.md` copies
  (including a stale "17 ADRs" claim; the repo now has 35).

Full detail in `CHANGELOG.md` under this version's `### Fixed` block.

## Why this is MINOR, not MAJOR

No scaffolded-service file was renamed or removed, no wire-schema
(`/predict`, prediction-log, ground-truth ingestion) changed, no
pre-commit hook contract changed, no ADR-recognized `make` target was
renamed or removed (RELEASING §1.3). Every addition — profiles, CCDS
mapping, uv support, onboarding, the coherence gate — is additive and
opt-in.

## Known follow-ons

- `templates/service/docs/ADOPTION.md` is a hand-maintained near-copy of
  `docs/ADOPTION.md` and remains only partially reconciled (missing the
  `doc-coherence` rows added to the root copy); not currently a registered
  vendored pair. Tracked for a future pass.
- The R7-audit-recommended on-ramps for batch-only pipelines and a
  Vertex AI / SageMaker "export surface" doc are still open.
- `check_doc_coherence.py` does not yet validate free-text "N ADRs" claims
  (the exact class of drift found in `llms.txt` / `ADOPTION.md` this
  pass) — deferred rather than rushing a repo-wide regex against
  historical/point-in-time documents that must not be "corrected".
- ADR-032 (BentoML) remains Proposed; no implementation is authorized
  until a Phase 1 contract test is written per its own staged plan.
