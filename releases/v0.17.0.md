# v0.17.0 — Vendor-Neutral Canonical Agentic Surface

Release date: 2026-06-08

MINOR release under [`docs/RELEASING.md`](../docs/RELEASING.md) §1.2 (new
`Status: Accepted` ADR + a backward-compatible surface change that does not
touch scaffolded service output). Headlined by **ADR-027**, which removes the
last vendor name from the canonical agentic layer, and bundles the Dependabot
GitHub Actions bumps that landed on `main` after the untagged `0.16.2` working
entry.

## What changed

### ADR-027 — the vendor-neutral surface

The agentic system was previously rooted in `.windsurf/`. When Windsurf
rebranded to Devin, that coupling forced a choice between renaming the
canonical store on every IDE rebrand or letting the directory name lie. ADR-027
breaks the coupling permanently:

- **`agentic/{rules,skills,workflows}/`** is now the single, human-authored
  canonical body store (15 rules, 16 skills, 12 workflows). It is the *only*
  place humans edit.
- **`AGENTS.md`** remains the sole behavior authority (AUTO/CONSULT/STOP).
- Every IDE directory is now *generated* from the canonical store via
  `scripts/sync_agentic_adapters.py`:
  - **`.devin/`** is a **mirror-surface** — full bodies copied byte-for-byte
    from `agentic/`, because Devin Desktop ingests directory bodies and cannot
    follow pointers. Humans never edit it; CI enforces byte-parity with
    `--check`.
  - **`.cursor/`, `.claude/`, `.codex/`** remain thin **pointer-surfaces** back
    to the canonical bodies + `AGENTS.md`.
- **`.windsurf/` and `.windsurf_context.md` are dropped.** `.devin_context.md`
  is the new Devin context pointer.

This amends **ADR-023** invariant I-4: the canonical source is `agentic/`, not
`.windsurf/`. `scripts/validate_agentic_manifest.py` now understands three
surface kinds — `canonical`, `mirror` (byte-parity enforced), and `pointer`
(thin-pointer validation).

### Why this is MINOR, not MAJOR

The rename is confined to the template's own **governance/agentic surface**. It
does **not** change the output of `templates/scripts/new-service.sh`, any
`templates/service/tests/contract/` shape, any overlay/namespace/ServiceAccount
name, any `common_utils` public callable, any Prometheus alert, or any
pre-commit hook contract. Per `docs/RELEASING.md` §1.1–§1.3 none of the MAJOR
triggers are touched, and §1.2 explicitly classifies a new `Status: Accepted`
ADR plus a backward-compatible surface as MINOR.
