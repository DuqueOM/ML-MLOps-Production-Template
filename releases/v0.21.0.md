# v0.21.0 — Native-Cloud-First Edge Protection, Monitoring-Station Audit Closure, and a Release Catch-Up

Release date: 2026-07-06

MINOR release under [`docs/RELEASING.md`](../docs/RELEASING.md) §1.2
(backward-compatible additions: new ADRs, new agentic surface, new
scaffolded-service files and Terraform modules, no renamed/removed
contract). This release closes **five initiatives** that completed
sequentially since `v0.20.0` (2026-07-01) without a version ever being
cut for any of them — a release-discipline gap this note both closes
and names, in the same spirit as the R4-driven policy `RELEASING.md`
itself documents (§1.4).

## What changed

### Edge protection — native-cloud-first, Cloudflare optional (ADR-042, D-38)

A six-station monitoring audit (Edge / Infrastructure / Inference /
Models / Logs & Traces / Business KPIs) found Edge to be the one real
gap: this template's Ingress resources shipped with no WAF, rate
limiting, or DDoS mitigation by default. The initial design proposed
Cloudflare as the reference implementation; the template maintainer
corrected this — the common case is a single-cloud deployment, and
forcing a third-party account + DNS delegation onto that case when the
chosen cloud already ships an equivalent native tool (integrated with
the same IAM model the rest of the template uses) is worse ergonomics
for no benefit. The shipped design:

- **Default**: Cloud Armor (GCP) / AWS WAFv2 + Shield Standard (AWS),
  wired via opt-in `k8s/components/edge-{gcp,aws}/` Kustomize
  Components (not referenced by any overlay until an adopter runs
  `/edge-setup` — same local-first-by-default philosophy as D-35).
- **Optional**: a Cloudflare Terraform module, for genuinely concurrent
  multi-cloud deployments or a zero-cloud-account learning path.
- **Governance**: anti-pattern **D-38**, rule `17-edge-protection`,
  skill `edge-audit` (AUTO, read-only — scans coverage the same way
  `rule-audit` does for one invariant domain), workflow `/edge-setup`
  (CONSULT). The verb-separated mode assignment mirrors ADR-039:
  `terraform apply` of edge resources is CONSULT in every environment
  including dev; disabling or loosening an existing rule is STOP in
  every environment, no exceptions.
- **Terraform** for all three (`infra/terraform/{gcp,aws,cloudflare}/`)
  validated with `terraform validate` against each provider's real,
  currently-published schema — not written from memory and assumed
  correct.
- **Monitoring**: `dashboard-edge.json` + two alerts
  (`EdgeProtectionMissing`, `EdgeAuditHeartbeatMissing`). Deliberately
  does not duplicate each cloud's own WAF-hit analytics — only tracks
  coverage and audit freshness, the one signal none of those consoles
  can answer.
- **`docs/runbooks/edge-protection-setup.md`**: setup steps + a cloud
  equivalence matrix. The three clouds' rate-limit windows are NOT
  interchangeable numbers (Cloud Armor: configurable, default 60s; AWS
  WAFv2: fixed 5-minute window, no native throttle; Cloudflare: fixed
  10s) — documented explicitly so a threshold isn't copied across
  clouds assuming equivalent behavior.

Surface counts: rules 17→18, skills 25→26, workflows 17→18,
anti-patterns D-01..D-37→D-01..D-38.

### Monitoring-stations audit closure

The same six-station audit found two more real gaps beyond Edge, both
closed in this release:

- **Inference — saturation**: new `inference_in_flight` /
  `inference_executor_capacity` gauges, a dashboard panel, and the
  `ExecutorSaturated` alert (info-severity capacity-planning signal).
- **Logs & Traces**: `RequestIDMiddleware` previously only wrote
  `request_id` to the log stream on the unhandled-exception path — a
  successful request produced no correlatable log line at all. Fixed
  with a structured access-log line on every non-probe request.
  Loki + Promtail added to the docker-compose demo (demo-only by
  design); Grafana datasource auto-provisioning also fixed a
  pre-existing gap where Prometheus itself was never auto-provisioned.
- **Business KPIs**: `dashboard-business.json` + the `cost-audit`
  skill now pushes `<service>_monthly_cloud_cost_usd` to Pushgateway.

`docs/observability/monitoring-stations.md` records the full coverage
map with file:line evidence, what's delegated to the adopter's
platform, and explicit N/A-with-revisit-trigger notes.

### R8 — Staff/Lead dual-repo audit

First audit round covering `agent-local` as a full subject alongside
this template. Verdicts: template 9.1/10, agent-local 7.9/10. Fixed two
local-DX findings in this template (root `pytest -q` collection
collision between three sibling `tests` packages; missing
`pytest-asyncio` in the root env) and revived a dead alertmanager
contract test masked by the collection bug.

### R9 Wave A — enterprise benchmark remediation

OpenSSF Scorecard (weekly + on-push), every third-party GitHub Action
pinned by commit SHA across all workflow files, `docs/COMPLIANCE_MAPPING.md`
(ADR-038, mapping existing controls to NIST AI RMF / ISO 42001 / EU AI
Act — explicitly not a certification claim), a portability &
escape-hatches matrix in `docs/ADOPTION.md`, and the CI-green
verification gate (`ci-green-verify` skill, `/ci-green` workflow,
**D-36**, ADR-039) wired as a hard precondition into `/release` and the
deploy skills.

### R10 — documentation-coherence hardening

Found and fixed four `docs/audit/*.md` files fully in Spanish and one
private companion repo named across 6 files in this public repo
(including a dead clickable URL) — this repo's own documentation
discipline had a real gap. Closed with anti-pattern **D-37**, ADR-040,
and `check_doc_coherence.py` C7 (`check_doc_language_and_privacy`), a
new deterministic gate scanning every tracked doc for non-English prose
and a private-repo denylist.

### ADR-041 — agentic skill and domain expansion

Four new skills (`pr-review`, `diagnose-bug`, `new-service-spec`,
`incident-postmortem`) and a `domain:` taxonomy
(`ml-data`/`platform-infra`/`security-compliance`/`sre-operations`) on
every skill's manifest entry for role-based discoverability.

Full detail for all five initiatives is in `CHANGELOG.md` under this
version.

## Why this is MINOR, not MAJOR

No scaffolded-service file was renamed or removed, no wire-schema
(`/predict`, prediction-log, ground-truth ingestion) changed, no
pre-commit hook contract changed, no ADR-recognized `make` target was
renamed or removed (RELEASING §1.3). Every addition across all five
initiatives — edge-protection components, the saturation/business/log
metrics, the R9/R10 governance gates, ADR-041's skills — is additive
and, where it touches a running service, opt-in.

## Known follow-ons

- Edge protection ships as opt-in Terraform + Kustomize Components; no
  scheduled CI job re-runs `edge-audit` automatically (every adopter's
  CI scheduling conventions differ — documented as a pattern in
  `docs/runbooks/edge-protection-setup.md`, not shipped as a cron).
- `dashboard-edge.json` intentionally does not surface per-rule WAF hit
  counts — an adopter needing that correlates the native cloud console
  with this dashboard's coverage panel manually.
- Cloud Armor's Managed Protection Plus and AWS Shield Advanced
  (~$3k/mo) remain explicitly out of scope (ADR-042 §4) pending a
  reported real need at production scale.
- ADR-032 (BentoML) remains Proposed; unchanged by this release.

## Audit deviation note

Per `docs/RELEASING.md` §6, cutting one release for five
sequentially-completed initiatives instead of one release per
initiative is itself a deviation from the target release rhythm (§4:
"never multiple MINORs per day," implying each initiative should
normally ship its own MINOR). This is recorded here rather than
silently bundled: the five initiatives accumulated in `[Unreleased]`
across 2026-07-02 through 2026-07-06 without a tag being cut, which
this release corrects going forward — not by re-litigating each
initiative's own bump level (each is independently a MINOR-shaped,
backward-compatible change), but by shipping the accumulated backlog as
one coherent release now instead of retroactively fabricating four
separate historical tags for work already merged to `main`.
