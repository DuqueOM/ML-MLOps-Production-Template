# v0.16.1 — CI/CD Template Drift Gate

Release date: 2026-05-15

Patch release under `docs/RELEASING.md`. Closes a Dependabot blindspot
that was already producing real divergence in the template, fixes the
four lagging references that existed at the time of the audit, and
adds an enforcement gate so the divergence cannot recur silently.

## What changed

### The blindspot

Dependabot's `github-actions` ecosystem only scans `.github/workflows/`
relative to the configured `directory:`. Action references in
`templates/cicd/*.yml` — the scaffolder inputs copied verbatim into
every adopter service by `templates/scripts/new-service.sh` — were
invisible to Dependabot. After every Dependabot PR that landed in
runtime workflows, the corresponding template references aged
silently. New services scaffolded today inherited stale CI references
and propagated the same bumps Dependabot had already merged upstream,
multiplying maintenance cost across every fork.

### The four real drifts found

A first-run scan of the gate confirmed the blindspot was not
hypothetical:

| Action | Runtime | Templates | Resolution |
|--------|---------|-----------|-----------|
| `actions/upload-artifact` | `v7` | `v4` | bumped templates → `v7` |
| `aquasecurity/tfsec-action` | `v1.0.3` | `v1.0.0` | bumped templates → `v1.0.3` |
| `bridgecrewio/checkov-action` | `v12.3102.0` | `v12.2752.0` | bumped templates → `v12.3102.0` |
| `sigstore/cosign-installer` | `v3.7.0` (pinned) | `{v3, v3.7.0}` (mixed) | normalized templates → `v3.7.0` |

Six template files touched: `ci.yml`, `ci-infra.yml`,
`deploy-common.yml`, `drift-detection.yml`, `retrain-service.yml`,
`terraform-plan-nightly.yml`.

### The gate

`scripts/check_cicd_template_drift.py` enforces: for every GitHub
Action used in both `.github/workflows/` and `templates/cicd/`, the
version set in templates must be a subset of the version set in
runtime. If templates use a version not present in runtime, the gate
fails with a structured diff showing the action, both version sets,
and the template-only versions to remove. Wired as
`cicd-template-drift` job in `validate-templates.yml`.

The gate runs on every PR. It is intentionally NOT in the
required-checks list codified by ADR-026 (same posture as
`common-utils-drift` from ADR-025). Promoting it to required would
require amending `docs/governance/branch-protection.md` and
ADR-026 §Revisit triggers.

### Documentation

- `docs/governance/cicd-templates-drift.md` — full rationale, scope,
  what it does NOT enforce, why a script and not a yaml-only check,
  revisit triggers (when this gate becomes obsolete).

## Why this matters

The template's value to adopters is partly that it ships modern,
secure CI defaults. Stale action versions in scaffolded services
undermine that promise without ever being visible. ADR-025
established the same anti-drift posture for `common_utils/`; this
release extends the pattern to CI templates. Both gates use the same
approach: a fast deterministic Python check that fails closed and
prints exactly what needs to change.

## What this release does NOT change

- No new dependencies.
- No public API changes (`/predict`, K8s identifiers, prediction
  schema all unchanged).
- The required-checks list in ADR-026 is unchanged: still six checks.
- No behavior change for adopters who do not run `make new-service`
  on this version — their existing scaffolded services are unaffected.

## Migration

No migration steps. Adopters on v0.16.0 update with `git pull`. New
services scaffolded after the upgrade automatically inherit the
synced CI template versions.

## Posture

Designed-ready (L1+L2+L3). Reinforces L3 (governance posture)
without claiming L4. Consistent with the position taken in ADR-024.

## Known follow-ons (scoped, not regressions)

time, violating the R4-L1 invariant its own contract test enforces._

- CI template version sync (`docs/governance/cicd-templates-drift.md`)
  is enforced for the scaffolded surface; the template repo's own
  `.github/workflows/` are tracked separately by Dependabot and may
  briefly diverge between releases.
- L4 real-cloud rollout evidence (GKE + EKS) remains the `v1.0.0`
  gate; v0.16.1 does not advance it.
