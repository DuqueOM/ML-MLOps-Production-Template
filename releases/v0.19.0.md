# v0.19.0 — Copier Scaffolding Migration (Wave 1)

Release date: 2026-06-30

MINOR release under [`docs/RELEASING.md`](../docs/RELEASING.md) §1.2 (a new,
backward-compatible scaffolding mechanism; `new-service.sh` keeps its CLI
contract as a thin wrapper). Headlined by **ADR-029** (Agentic Adoption
Contract) and **ADR-030** (Copier-based scaffolding migration) — Wave 1 of
the industry-adoption program tracked in
[`docs/audit/ACTION_PLAN_ADAPTABILITY.md`](../docs/audit/ACTION_PLAN_ADAPTABILITY.md).

## What changed

### Copier replaces the manual `cp` + `sed` scaffolder

- `copier.yml` at the repository root, `_subdirectory: templates/service`,
  custom Jinja2 delimiters `{@ @}` (chosen over the default `{{ }}` because
  the template body is full of literal `${{ }}` GitHub Actions expressions
  and Python f-strings — see ADR-030 §2.2 for the collision analysis).
- `templates/scripts/new-service.sh` is now a thin wrapper around
  `copier copy`, preserving its existing 2–4 positional-argument CLI so
  existing invocations keep working.
- Post-generation tasks (`_tasks` in `copier.yml`) run
  `scripts/sync_agentic_adapters.py` then
  `scripts/validate_agentic_manifest.py --strict`, so every freshly
  scaffolded service ships with a coherent agentic surface or fails loud.
- `copier update` is now the documented template-upgrade path
  (`MIGRATION.md` §Copier scaffolding migration), replacing the old manual
  drift-diffing workflow.

### Two new anti-patterns (D-33, D-34)

- **D-33** — manual file copying or sed-based placeholder substitution in
  the scaffolder is forbidden; the scaffolder MUST delegate to
  `copier copy`. Enforced by `scripts/test_scaffold.sh`.
- **D-34** — unquoted `{@ @}` Jinja tokens in YAML list items are invalid
  YAML (`@` cannot start a bare token); all such tokens MUST be quoted.
  Enforced by a zero-hit `rg` check over `templates/service/`.
- New rule `agentic/rules/15-template-lifecycle.md` documents both.

### New agentic surface

- Skill `scaffold-update` (CONSULT) + workflow `/scaffold-update`: diff →
  re-sync → re-validate → run `rule-audit` after a `copier update`.
- Manifest entries with `authority:` anchors for the new rule, skill, and
  workflow; `rule-audit` catalogue extended to D-34.

### Positioning

- README §"How this compares": an honest comparison table against Made
  With ML, Cookiecutter Data Science, and ZenML — explicit "borrow ideas,
  never fork" framing (ADR-029).
- `docs/audit/ACTION_PLAN_ADAPTABILITY.md`: the living tracker for the full
  Wave 0–4 adoption program, including a license/provenance guardrail
  confirming the Apache-2.0 license is unaffected by the ergonomics
  borrowed from reference templates.

## Why this is MINOR, not MAJOR

`new-service.sh`'s CLI contract (positional args, output file list) is
unchanged from an adopter's perspective — Copier is an implementation
detail behind the same wrapper. No overlay/namespace/ServiceAccount
rename, no `common_utils` public-callable change, no wire-schema change
(RELEASING §1.1–§1.3).

## Known follow-ons

- Waves 2–4 (local-first stack profiles, CCDS layout mapping, uv adoption,
  guided tutorial, adopter onboarding) are tracked in the same action plan
  and ship in `v0.20.0`.
- `scripts/test_scaffold.sh` is the D-33 enforcement point; broader Copier
  render-fidelity testing (property-based fuzzing of Jinja substitution)
  remains a candidate for a future minor.
