# v0.18.0 — R6 Audit Closure: Surface Loadability + Template-Context CI Lane

Release date: 2026-06-10

MINOR release under [`docs/RELEASING.md`](../docs/RELEASING.md) §1.2
(backward-compatible additions to the agentic surface, CI, and test
infrastructure; no scaffolded-service output change). Headlined by the
**R6 audit** ([`docs/audit/ACTION_PLAN_R6.md`](../docs/audit/ACTION_PLAN_R6.md)):
an evidence-based review that executed the repo's own validators and full
test suite, found the Claude Code skill surface silently undiscoverable
and a CI coverage hole that left 8 contract tests red on `main`, and
closed every S0/S1 finding in this release.

## What changed

### S0-1 — Claude Code skill surface is now actually loadable

`.claude/skills/<id>.md` flat pointers were never discovered by Claude
Code, which only loads `<id>/SKILL.md` directories with YAML frontmatter.
The 12 workflows worked; the 16 skills were invisible.

- `scripts/sync_agentic_adapters.py` renders the `claude` pointer-surface
  as `.claude/skills/<id>/SKILL.md`, with `name` + `description`
  frontmatter extracted from the canonical `agentic/skills/<id>/SKILL.md`.
  The body remains a thin pointer (ADR-027 contract intact).
- `scripts/validate_agentic_manifest.py` validates the new layout AND
  adds **surface-loadability checks**: claude skill pointers must carry
  parseable frontmatter with a non-empty description — pointer
  *existence* alone is no longer accepted (the failure class behind
  S0-1 was precisely "exists but unloadable").
- Verified live: all 16 skills become invocable in a Claude Code session.

### S0-2 — Template-context CI lane (8 silently-red tests fixed)

No CI lane executed the full `templates/service/tests` suite against the
template repo itself; `policy-tests.yml` covers `tests/policy/` only and
`validate-templates.yml` runs a post-scaffold subset. Eight contract
tests were red on `main` with nothing watching:

| Fix | Detail |
|-----|--------|
| Dashboards inventory | `dashboard-dora.json` row + panels section added to `docs/observability/dashboards-inventory.md` |
| NetworkPolicy egress contract | Test updated to the May-2026 default-deny base contract (every overlay patches egress; dev ships a permissive patch deliberately); base manifest now carries the `OVERLAY-OVERRIDE REQUIRED` banner |
| Release-notes follow-ons | `## Known follow-ons` sections backfilled into `v0.16.0.md` / `v0.16.1.md` |
| K8s name vocabulary | URL-style kebab regex no longer false-positives on `src/{service}/…` Python module paths (D-32 says those are snake-case by design) |

New lane: [`.github/workflows/template-context-tests.yml`](../.github/workflows/template-context-tests.yml)
runs the full suite with `-m "not scaffold_context and not locust_parity"`
on every push/PR to `main`. Scaffold-context tests (generated OpenAPI
snapshot, `data/*` dirs, trained-model e2e) are marked `scaffold_context`
(registered in `templates/service/pyproject.toml`) and stay covered by
the scaffold smoke + golden path.

Hardening discovered while building the lane: importing **locust**
gevent-monkey-patches ssl/socket process-wide and deadlocks anyio
`TestClient` lifespans that run afterwards (reproduced as a 55-minute
`epoll_wait` hang with zero CPU — the worst CI failure mode, a hang
rather than a failure). Three-layer fix: `load_test.py` is
`collect_ignore`d in conftest, the lane passes `-p no:locust` (locust
self-registers as a pytest plugin), and the Locust↔API parity contract
(`test_load_payload_matches_schema.py`, new `locust_parity` marker) runs
in its own pytest invocation where the monkey-patch lands before asyncio
exists.

### S0-3 — `rule-audit` skill catches up to D-32

The compliance-scanner skill still said "D-01 through D-27" while the
canonical catalogue ships D-01..D-32. The skill's frontmatter,
catalogue, and checks now cover D-28..D-32, and the anti-pattern count
consistency test extends to skill bodies.

### S1 — Hygiene and coherence

- **MCP registry**: `docker` (local daemon debugging; never pushes
  registry images) and `postgres` (read-only closed-loop SQL) added to
  `templates/config/mcp_registry.yaml` with risk modes, skill links, and
  per-surface install matrix; `docs/agentic/mcp-portability.md`
  re-rendered. AGENTS.md §MCP Integrations drops the stale
  `~/.codeium/windsurf/` path for a per-surface config table, and a
  placeholder-only [`.mcp.json.example`](../.mcp.json.example) ships for
  Claude Code project scope (live `.mcp.json` is gitignored).
- **Test isolation** (S1-2): autouse `os.environ` snapshot/restore
  fixture in `templates/service/tests/conftest.py` — environment leakage
  (`PREDICTION_LOG_ENABLED=true`) previously cascaded into 52 spurious
  lifespan errors when optional deps were missing.
- **Versioning clarity** (S1-3): [`releases/README.md`](README.md)
  documents the legacy `v1.x` line vs the active `v0.x` line and the
  re-reserved `v1.0.0` L4 gate; CLAUDE.md updated (S1-4: rule count 15,
  releases pointer).
- **ADR-028 (Proposed)** — LLM-assist integration plan for template
  maintenance and Day-2 operations: four bounded lanes reusing existing
  contracts (ADR-019 Phase 2 behind CONSULT, memory-plane retrieval,
  drift/incident triage summarization, eval harness); explicitly
  recommends **against** fine-tuning dedicated models at this scale.
  Requires maintainer acceptance before any implementation.

## Why this is MINOR, not MAJOR

No `templates/scripts/new-service.sh` output change, no contract-snapshot
shape change, no overlay/namespace/ServiceAccount rename, no
`common_utils` public-callable change, no alert or pre-commit contract
change (RELEASING §1.1–§1.3). The `.claude/skills/` layout change affects
only a generated pointer-surface regenerated by sync.
