# v0.22.0 — Four capabilities that were documented, guarded, and not working

Release date: 2026-08-07

MINOR release under [`docs/RELEASING.md`](../docs/RELEASING.md) §1.2. The
additions are backward-compatible. The fixes are not behaviour changes to
any shipped contract — they are repairs to contracts that were **asserted
in documentation, covered by passing tests, and non-functional**.

## The theme, named plainly

This release is not a feature release. It closes four defects that share a
shape worth stating outright, because the shape is the finding:

| Capability | Asserted in | Reality |
|---|---|---|
| `copier update` path | ADR-003 + 4 other places | No answers file was ever emitted |
| Secret-scan parity local↔CI | `.pre-commit-config.yaml` header | Two different allowlist dialects |
| Phase-1 disclosure guard | `test_phase0_disclosure.py` | 6/6 skipped, 0 enforced |
| ADR-019 shadow lane | README §"Agentic CI self-healing" | 0 runs in its entire life |

In every case a test passed. In every case it passed *because of how it was
written*, not because the thing worked:

- The scaffolder suite carried a comment asserting the missing answers file
  was **expected** — encoding the defect as intended behaviour.
- The disclosure guard opened each check with `skip if the ADR is no longer
  Phase 0`; the ADRs advanced, and it enforced nothing thereafter.
- The shadow-lane suite guarded *"the workflow is read-only"* and never
  *"the workflow can run"*.
- The secrets gate ran two versions that disagreed about which allowlist
  dialect to honour, silently, in both directions.

The corrective work therefore includes a guard for each, and **every guard
was verified by breaking it on purpose** — a guard that cannot be observed
to fail is the failure mode this release is about.

## What changed

### `copier update` works (ADR-003 blocker)

`copier copy` produced services with no `.copier-answers.yml`, so
`copier update` could not run and every generated service was "a fork with
extra steps" — the outcome ADR-003 §"Generation, not copying" exists to
prevent. The template promised the capability in **five** places while
structurally lacking it.

Root cause of the silence: `copier.yml` sets custom `_envops`
(`variable_start_string: "{@"`), so the stock Copier filename form
`{{ _copier_conf.answers_file }}` does not render — Copier emits it as a
*literal* filename rather than erroring.

Verified end-to-end for the first time in this repo's history: scaffold →
`git init` → template change → `copier update` pulls it and `_commit`
advances.

**Adopters with existing services are not automatically fixed.**
`MIGRATION.md` carries the recovery procedure.

### Secret-scan parity between local and CI

gitleaks changed its config dialect at 8.25. The hook pinned `v8.21.2`; CI
inherited whatever `gitleaks-action` bundled. Below 8.25 the plural
`[[allowlists]]` tables are silently ignored; at or above it the singular
`[allowlist]` form is rejected. The two scanned the same tree under
different rules with no signal from either side.

The AUDIT R11 "L-2" compatibility shim had become the blocker for the
upgrade. Removed; CI now installs an explicitly pinned binary and
`scripts/check_gitleaks_pin.py` fails the build on drift across the three
declaration sites.

Verified: full-history scan, 342 commits, `no leaks found`.

### The disclosure guard is armed again

Rewritten to be phase-aware rather than phase-pinned: it derives its
requirement from the ADR's declared phase, fails rather than skips when it
cannot, and lifts only when an ADR declares its runtime live.

**6 skipped / 0 enforced → 10 passed / 0 skipped.**

### The ADR-019 shadow lane can fire

`workflow_run.workflows` matches a workflow's `name:` field; the list held
filename stems. Nothing matched, so the lane recorded zero runs while
reporting `state=active`, and ADR-019's Phase 1 → Phase 2 gate ("14 days of
shadow precision data") was unsatisfiable by construction rather than by
choice.

Verified post-merge: run count **0 → 2**, `event=workflow_run`,
`conclusion=skipped` — correct, since the job is gated on upstream
`conclusion == 'failure'` and CI was green. The clock is running.

## Adopter-visible changes

See [`MIGRATION.md`](../MIGRATION.md) §"v0.21.0 → v0.22.0". The one that
needs real attention: if you customised `.gitleaks.toml` and it carries a
singular `[allowlist]` table, gitleaks >= 8.25 will refuse to load it.

## Known follow-ons

Deferred deliberately, not overlooked:

- **Ruff migration** (`black` + `isort` + `flake8` → `ruff`). A 43-file
  cascade touching normative documents that mandate the toolchain, so it
  needs its own ADR. Measurement removed the urgency argument: the current
  suite runs `--all-files` in **2.62 s** warm, inside the `< 5 s` target
  the config claims. The remaining case is maintenance surface, not speed.
- **Template ADR namespacing.** Generated services ship six template ADRs
  with no namespace prefix, colliding with the adopter's own numbering.
- **Shadow-lane precision data.** The lane can fire but has classified
  nothing yet. Phase 2 stays blocked on 14 days of real data — now
  obtainable rather than impossible.
